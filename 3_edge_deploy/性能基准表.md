## 1. 性能基准表 · 鲁班猫三行

| 模型 | 输入 | 精度 | NPU 单帧耗时 均值/中位/P99 | 仅 NPU 折算帧率 | 板端精度 | 验收 |
|---|---|---|---|---|---|---|
| 信用卡欺诈 MLP | 1×29 | INT8 | **0.213 / 0.217 / 0.360 ms** | **4699 fps** | AUPRC 0.53211、ROC-AUC 0.88661 | **通过** |
| 肺炎 CNN | 1×3×224×224 | INT8 | 4.09 / 4.08 / 4.37 ms | 244 fps | AUROC 0.5465 | **不通过**（转换失效，见 §4） |
| YOLOv8n 人员检测 | 1×3×640×640 | fp16 | 50.88 / 49.36 / 54.17 ms | 19.7 fps | 检出率 100% | **通过** |
| YOLOv8n 人员检测 | 1×3×640×640 | INT8 | 41.29 / 41.22 / 43.99 ms | 24.2 fps | 检出率 0% | **不通过**（见 §4） |

> 「仅 NPU 折算帧率」= 1000 / 单帧 NPU 均值，不含预处理/解码/绘制。
> 端到端帧率要低得多（YOLOv8n 端到端实测 8.6~10.3 fps，瓶颈在图像缩放
> 与 NMS，不在 NPU）。

## 3. 量化收益（同一模型 fp16 vs INT8）

| 模型 | fp16 单帧 | INT8 单帧 | 加速比 | 精度变化 |
|---|---|---|---|---|
| 肺炎 CNN | 7.09 ms | 4.09 ms | **1.73×** | AUROC 0.6343 → 0.5465（两者都已失效，见 §4） |
| YOLOv8n | 50.88 ms | 41.29 ms | **1.23×** | 检出率 100% → 0%（失效，见 §4） |
| 信用卡欺诈 MLP | 0.221 ms | 0.213 ms | 1.04× | AUPRC 0.51676 → 0.53211（**反而更好**） |

结论：INT8 在本板上确有加速（CNN 1.7×、YOLO 1.2×），但**必须先验证精度再交付**——
本轮两个视觉模型的 INT8 都没通过精度验证。

## 4. 精度验证明细

### 4.1 信用卡欺诈 MLP —— 通过

训练集侧最优阈值是 **0.77**（不是 0.5；用 0.5 会把大量正常样本误判为欺诈）。

| 指标 | INT8 RKNN | 浮点 ONNX（板端 CPU） | 判据 | 结论 |
|---|---|---|---|---|
| 判定一致率 | **99.9561%** | — | ≥ 99% | 通过 |
| AUPRC | 0.53211 | 0.51740 | — | — |
| AUPRC 降幅 | **−0.01471** | — | ≤ 0.03 | 通过（量化后反而略优） |
| 预测正类占比 | 0.00126 | — | 接近真实 0.00172 | 通过 |

对照：用 `normal` 算法 + 不裁剪校准集转换时，AUPRC 掉到 0.48372（降幅 0.03368，**超标**）。
换 `kl_divergence` 并把校准集截断到 ±16 后才通过。调参过程见 `README_RK3588S.md`。

### 4.2 肺炎 CNN —— 板端链路正确，但 RKNN 模型失效

分两层看，这一点很关键：

| 路径 | 准确率 | 肺炎查全率 | AUROC | 混淆 (tp/fp/fn/tn) |
|---|---|---|---|---|
| **ONNX（板端 CPU 跑）** | **0.8500** | 0.9975 | **0.9628** | 397 / 95 / 1 / **147** |
| 训练侧 PyTorch 参照 | 0.8500 | 0.9975 | 0.9629 | 397 / 95 / 1 / 147 |
| RKNN fp16 | 0.6219 | 1.0000 | 0.6343 | 398 / 242 / 0 / **0** |
| RKNN INT8 | 0.6203 | 0.9975 | 0.5465 | 397 / 242 / 1 / **0** |

**板端预处理、数据、评估口径都是对的**——ONNX 在板子上与训练侧逐项完全一致，
逐位相同到混淆矩阵。失效发生在 **ONNX → RKNN 转换**这一步，且浮点版同样失效，
所以不只是量化的问题。详见 `README_RK3588S.md` 的「已知问题」。

### 4.3 YOLOv8n —— fp16 通过，INT8 失效

| 版本 | 框坐标通道 max | 类别分通道 max | 检出率 |
|---|---|---|---|
| fp16 RKNN | 641 / 637 / 291 / 349 | **0.8140** | **100%** |
| INT8 RKNN | 643 / 643 / 300 / 361 | **0.0000** | 0% |

框坐标正常、类别分**精确为 0**——分类头在 INT8 下整个失效。
把校准集从 2 张换成 20 张 COCO 图重转后依然如此，所以「校准图太少」不是根因。

## 5. 复现命令

```bash
# 任务卡 6 · MLP（阈值必须用 0.77）
python3 ~/edge/infer_mlp_rknn.py --rknn models/mlp_fraud.rknn \
        --onnx models/mlp_fraud.onnx --splits models/mlp_splits.npz \
        --threshold 0.77 --report ~/edge/out/board_mlp_report.json

# 实验二 · 肺炎 CNN
python3 ~/edge/infer_cnn_rknn.py --rknn models/pneumonia.rknn \
        --preprocess models/preprocess.json --manifest models/test_manifest.txt \
        --image-root ~/chest_xray --report ~/edge/out/board_cnn_report.json

# 任务卡 14 · YOLO 人员检测（板子无摄像头，用图片/视频文件当源）
python3 ~/edge/cam_person_detect.py --rknn models/yolov8n_fp.rknn \
        --source models/bus.jpg --frames 1 --headless \
        --save-shot ~/edge/out/bus_shot.jpg --report ~/edge/out/board_yolov8_report.json

# CPU 占用
python3 ~/edge/cpu_load_harness.py
```

各脚本都会把结果写进 `~/edge/out/*_report.json`；本表的数字就是从这些
report 里取的，原始文件同步一份在 `artifacts/board_reports/`。
